# Strata 環境・最適化レポート

作成日：2026年10月3日（日本時間）

Strataは起動・応答確認済み。64Kの会話長を維持し、CPU/GPUの処理分担を調整した。英語のコード生成テストでは、繰り返し実行時の生成速度が平均33.0から35.9 tokens/sに向上した（約8.8%）。

## 1. PCと実行環境

| 項目 | 内容 |
|---|---|
| OS | Windows 11、ビルド26300 |
| CPU | AMD Ryzen 7 5700X、8コア／16スレッド |
| メモリー | 32 GB（検出値31.9 GiB） |
| GPU | AMD Radeon RX 9070 XT、VRAM 16 GB、gfx1201 |
| ストレージ | G: のNVMe SSD、SHGP31-1000GM（1 TB） |
| インストール先 | `G:\Strata` |
| モデルデータ | `G:\Strata\Strata-data` |
| Python | 3.13.15、フォルダー内の専用環境 `.venv` |
| Strataエンジン | 0.1.38、AMD HIPバックエンド |
| リポジトリー | Niko1221/Strata、コミット `99f3dbd` |

## 2. 現在の設定

| 項目 | 設定 |
|---|---|
| モデル | Qwen3.8-Flash-Next Coder IQ1_M |
| 最大会話長 | 65,536トークン（64K） |
| 会話キャッシュの精度 | int8（8ビット） |
| CPU並列数 | `--pool-workers 7` |
| GPUへの処理振り分け | `--pcie-frac 0.65` |
| GPUのモデルキャッシュ | `--expert-cache auto` |
| 入力処理 | `--prefill auto` |
| 先読み生成 | MTP有効、`--spec 4`、`--spec-min-p 0.5` |
| RAM利用 | `--resident-experts`、ページ固定なし |
| AMD向け計算調整 | gfx1201用hipBLASLtテーブル有効 |
| 画像入力／実験的speed projection | いずれもオフ |
| 公開範囲 | このPC内のみ、`127.0.0.1:8080` |

`pcie-frac`は、GPUキャッシュにない専門家のうち、CPUで計算せずGPUへ転送する割合を調整する値。GPU全体の使用率が65%という意味ではない。

最終測定時は、約19.5 GiBの専門家データをRAMに保持でき、専門家データのファイル読み込みは0だった。GPUには2,443個の専門家（約4.7 GiB）を保持していた。初回起動ではRAM確保に失敗しSSD読み込みへ切り替わっていたため、他のアプリのメモリー使用量によって速度が変わる。

## 3. 最適化の内容と比較

元の設定をバックアップし、モデルを再起動して各設定を3回ずつ測定した。比較値は、キャッシュの影響を分けるため2・3回目の生成速度の平均を使用。

| CPU並列数 | PCIe振り分け | 生成速度の平均 | 判定 |
|---:|---:|---:|---|
| 7（元の自動設定） | 自動、実測0.39 | 33.0 tokens/s | 比較基準 |
| 7 | 0.65 | 36.6 tokens/s | 最速、採用候補 |
| 15 | 0.65 | 19.8 tokens/s | 遅いため不採用 |
| 15 | 自動、実測0.39 | 19.8 tokens/s | 遅いため不採用 |
| **7** | **0.65** | **35.9 tokens/s** | **再起動後の再測定でも改善、保存済み** |

64K、int8、モデルは維持した。CPU並列数を増やすより、7並列でGPUへの振り分けを増やす設定が、この測定では速かった。

## 4. 最適化後の性能

測定条件：同じ英語のCSV平均計算関数の作成依頼、思考オフ、temperature 0、seed 42、出力上限256トークン。ローカルのストリーミングAPIで計測した。

| 回数 | 最初の回答文字まで | 生成速度 | 完了まで |
|---|---:|---:|---:|
| 1回目（再起動後） | 2.94秒 | 22.3 tokens/s | 14.34秒 |
| 2回目 | 0.22秒 | 36.2 tokens/s | 7.25秒 |
| 3回目 | 0.24秒 | 35.5 tokens/s | 7.40秒 |

先に実施した日本語のStrata Chatテスト（最適化前）は、生成速度11.2／23.7／26.2 tokens/s、完了まで28.0／11.3／10.0秒だった。質問・サンプリング条件が異なるため、上の英語テストとの直接比較はできない。

いずれも256トークンで途中終了した速度測定であり、コードの完成度を評価したものではない。日本語テストでは文章の繰り返しも見られた。繰り返し実行では入力やモデルのキャッシュが効くため、別の質問・長い入力・他アプリ使用中に同じ速度を保証しない。最適化比較では実行時のRAM確保量も変化しており、改善のすべてをPCIe設定だけの効果とは断定できない。64K全体を埋める長文テストは未実施。
